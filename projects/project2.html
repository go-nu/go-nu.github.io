청각 장애인을 위한
IoT 소리 감지 알림 시스템

라즈베리파이와 딥러닝(CNN)으로 주변 소리를 실시간 분류·방향 감지하고, Firebase Cloud Messaging을 통해 안드로이드 앱과 스마트 워치에 즉시 알림을 전달하는 IoT 캡스톤 프로젝트입니다.

01 · OVERVIEW

프로젝트 개요

청각 장애인은 사이렌·경적·화재 경보 등 위험 소리를 인지하지 못해 일상 속 안전 위협에 그대로 노출됩니다. 본 프로젝트는 이 문제를 해결하기 위해 엣지 디바이스(라즈베리파이)에서 소리를 수집·분류하고, 클라우드를 거쳐 스마트폰과 웨어러블에 즉각 알림을 전달하는 종단 간(end-to-end) IoT 시스템을 구현했습니다.

3인 팀 프로젝트로 진행했으며, 저는 라즈베리파이 추론 실행 · Firebase Cloud Messaging 전송 · Android 알림 수신 · 스마트 워치 알림 연동 을 담당했습니다. CNN 모델이 분류한 결과를 실시간으로 사용자 기기까지 안정적으로 전달하는 전체 파이프라인을 설계하고 구현했습니다.

04 · FEATURES

주요 기능 (담당 파트)

1
라즈베리파이 엣지 추론 PyAudio로 수집한 오디오를 librosa로 MFCC 특징 추출 후 학습된 CNN 모델(model.h5)에 입력해 7가지 소리를 실시간 분류합니다. FFT 기반 음량 임계값(20,000)을 초과할 때만 5초 녹음을 시작해 불필요한 추론을 최소화했습니다.
2
Firebase Cloud Messaging 알림 전송 firebase-admin SDK로 분류 결과를 Realtime Database에 업로드하면, Firebase Functions의 onWrite 트리거가 감지해 스마트폰과 웨어러블 토큰으로 FCM 푸시 알림을 자동 전송합니다. 값이 실제로 변경된 경우에만 알림을 보내도록 이전 값과 비교 로직을 추가했습니다.
3
Android 앱 알림 수신 및 UI 업데이트 Firebase Realtime Database를 실시간 구독해 소리 종류에 따라 아이콘과 텍스트 색상을 즉시 변경합니다. 위험 소리(사이렌·경적·화재)는 빨간색, 일반 소리(주행음·자전거)는 파란색으로 구분해 시각적으로 직관적인 UI를 제공합니다. MyFirebaseMessagingService를 통해 백그라운드에서도 FCM 알림을 수신합니다.
4
스마트 워치 진동 알림 연동 FirebaseDatabaseService 백그라운드 서비스가 소리 방향 변경을 감지해 방향별로 서로 다른 진동 패턴을 출력합니다. 동(짧은 1회) · 서(긴 1회) · 남(짧은 2회) · 북(긴 2회)으로 소리 방향을 촉각으로 즉시 구분할 수 있습니다.

05 · TROUBLE SHOOTING

문제 해결 과정

문제: 소리가 없을 때도 지속적으로 추론이 실행되어 CPU 과부하 발생

라즈베리파이의 제한된 연산 자원에서 상시 추론을 실행하면 CPU 사용률이 100%에 달해 시스템이 불안정해졌습니다. FFT로 현재 음량을 계산하고 임계값(20,000)을 초과할 때만 녹음과 추론을 시작하는 음량 트리거 방식으로 전환했습니다. 이를 통해 불필요한 연산을 크게 줄이고 안정적인 실시간 동작이 가능해졌습니다.

문제: Firebase DB 값이 같아도 onWrite 트리거가 발동되어 중복 알림 전송

Firebase Functions의 onWrite는 값 변경 여부와 무관하게 쓰기 이벤트가 발생하면 항상 트리거됩니다. change.before와 change.after를 비교해 sound_type 또는 sound_direction 중 하나라도 실제로 달라진 경우에만 FCM 메시지를 전송하도록 조건 분기를 추가해 중복 알림 문제를 해결했습니다.

문제: 앱이 백그라운드 상태일 때 소리 방향 변경에 따른 진동이 동작하지 않음

Activity가 백그라운드로 전환되면 Firebase Realtime Database 리스너가 해제되어 방향 변경을 감지하지 못했습니다. 방향 감지와 진동 출력 로직을 별도의 START_STICKY 백그라운드 서비스(FirebaseDatabaseService)로 분리해, 앱이 포그라운드가 아닌 상태에서도 지속적으로 동작하도록 수정했습니다.

06 · RETROSPECTIVE

프로젝트 회고

✅
잘 된 점

마이크 → 추론 → DB → FCM → 앱·워치로 이어지는 전체 파이프라인을 직접 설계하고 연결했습니다. 각 컴포넌트를 독립적으로 구현해 디버깅이 용이했습니다.

🔧
아쉬운 점

라즈베리파이의 자원 제약으로 추론 지연이 발생했습니다. TensorFlow Lite로 모델을 경량화하거나, 방향 감지 알고리즘을 개선했다면 응답 속도를 더 높일 수 있었을 것입니다. 또한 Firebase 서비스 계정 키를 환경 변수로 완전히 분리하지 못한 점이 아쉽습니다.

💡
배운 점

엣지 컴퓨팅 환경의 자원 제약을 직접 경험하며 경량화와 트리거 기반 설계의 중요성을 체감했습니다. Firebase Functions의 이벤트 기반 아키텍처와 FCM 토큰 관리, Android 백그라운드 서비스 생명주기에 대한 이해를 실전에서 쌓을 수 있었습니다.

🚀
다음 목표

학습시킨 음성 데이터에 노이즈가 많아 구분 정확도가 아쉬웠습니다. 노이즈가 없는 깨끗한 데이터를 사용하거나 노이즈를 제거하는 전처리 방식을 추가하고 싶습니다. 또한 다중 마이크 배열 신호 처리를 개선해 방향 정확도를 4방향에서 8방향 이상으로 확장하는 것을 시도해보고 싶습니다.
